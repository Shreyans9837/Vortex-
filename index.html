Example: AI refund agent

An agent requests a $50 refund.

VORTEX authenticates the agent, checks permission and limits, accepts the controlled action, records its result, verifies supplied cryptographic evidence when present, and appends the event to the audit chain.

The architecture keeps real external side effects behind explicit adapters rather than pretending that a database record is a payment.

Security

Controls designed around failure, replay and tampering.

Gateway credential

Protected API routes require a server-side gateway credential.

Per-agent credential

Agent actions require a separate credential scoped to the registered agent.

Atomic nonce claim

Agent + nonce is enforced by a database primary key inside a write transaction.

Daily limits

Spending limits are evaluated and updated inside the same transaction as the audit record.

Hash chain

Each audit record commits to the previous record, allowing integrity verification.

Real ZK boundary

Groth16 verification uses SnarkJS and a generated verification key; missing artifacts are never reported as valid proof.

Audit layer

Integrity is independently checkable.

Protected ledger and metrics routes remain operator-only. The UI never fabricates audit records.

Ledger verification

VORTEX recomputes the hash chain from genesis and checks every record's previous hash and current hash. A mismatch is surfaced as corruption/tampering rather than hidden.

FAQ

Clear boundaries matter.

Is VORTEX an AI model?

No. It is infrastructure around AI agents.

Is SHA-256 a ZK proof?

No. A hash is not a zero-knowledge proof. VORTEX treats real Groth16 proving and verification as a separate cryptographic subsystem.

Does the current engine perform real-world payments?

The core runtime records controlled execution. Real settlement is an explicit optional adapter and should only be enabled with dedicated keys, limits and operational controls.

What does “production-ready” mean here?

A deployable MVP is not the same as a security-audited production system. Further external security review, load testing, operational controls and customer validation are required before making that claim.
